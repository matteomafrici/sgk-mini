# Validation

Reproducible validation of the sgk-mini stack.

## Analytical (geometry → feature → physics)

The C# stage generates the hollow-cylinder voxel geometry, extracts features,
and writes the analytical annular-flow benchmark:

```bash
dotnet run --project src/SGK.Geometry/ -- --auto-exit
```

Outputs land in `output/` (gitignored). The runtime asserts the invariants
(schema, voxel round-trip, laminar regime, wall no-slip) and fails loudly if
they break.

## CFD cross-check (OpenFOAM)

`openfoam/annulus_cyclic/` is a self-contained OpenFOAM case for steady,
fully developed, laminar axial flow in a concentric annulus. It uses cyclic
periodic boundaries with `meanVelocityForce`, which removes developing-flow
artifacts and gives one identical solution at every cross-section.

Only the dictionary sources are versioned; `constant/polyMesh/`, the time
directories and logs are generated by `run_annulus.sh` and gitignored.

Prerequisites:

- OpenFOAM v2606 with its environment available via `etc/bashrc`
  (default `~/opt/OpenFOAM/OpenFOAM-v2606/etc/bashrc`, override with
  `FOAM_BASHRC`).
- A Python with numpy (default `~/data/venvs/sgk-mini/bin/python`, override
  with `PYTHON`).

Run:

```bash
dotnet run --project src/SGK.Geometry/ -- --auto-exit   # benchmark first
./validation/run_annulus.sh                             # blockMesh + simpleFoam + report
./validation/run_annulus.sh --check                     # non-zero exit on drift
```

`validate_annulus.py` compares the solver field against the closed-form
solution. It reads the pressure gradient from the solver log (no magic
numbers) and the benchmark from `output/hollow-cylinder.physical-case.json`.

### Reference result (Omarchy, 2026-11-18)

80×100×3 cells, cyclic periodic, 2000 iterations (~86 s serial), voxel size
0.2 mm:

| Metric | Value |
|---|---|
| mean \|err\| / Umax | 3.65 % |
| max \|err\| / Umax | 7.14 % |
| Umax error | 0.28 % |
| pressure-gradient error | 1.04 % |
| flow-rate error | 0.50 % |

The peak velocity is compared against the continuous analytical maximum
(evaluated where `du/dr = 0`), not against the largest of the 17 profile
samples. The sampled peak understates the true peak by about 0.03 % and is kept
in the record as `SampledMaxVelocityMPerS` for traceability.

**Why the flow-rate error is 0.50 % and not noise.** The wedge spans 30° in
three cells of 10°, so the cross-section is a polygon, not an annulus. A chord
over 10° encloses `sin(θ)/θ = 0.99493` of the circular sector, i.e. the mesh has
**0.507 % less flow area** than the geometry it represents. The measured
flow-rate error is 0.4986 %. These are the same number: the error is fully
explained by the angular discretisation, and it would disappear with a proper
2D axisymmetric (`wedge`) mesh or with more angular cells.

This also explains why the pressure-gradient error went from 0.74 % to 1.04 %
when the voxel size moved to 0.2 mm. The previous 0.3 mm reconstruction produced
radii 3 µm off (Ri 8.0030 instead of 8.0000), whose area was 0.29 % too small;
that error happened to cancel part of the 0.51 % mesh bias. With the geometry
now accurate to 0.1 µm, the mesh bias is no longer masked, and the honest number
is the larger one.

**`blockMeshDict` carries the radii as literal numbers.** `validate_annulus.py`
checks them against the reconstructed radii in the benchmark record and fails
with an explicit message if they drift, so the mesh cannot silently represent a
different geometry.

The near-wall bias is systematic and inherent to second-order finite-volume
discretization at this aspect ratio (~35–55), not an implementation defect.

## Figures

`plot_annulus.py` (run automatically by `run_annulus.sh`) writes the figures
embedded in the top-level README to `validation/figures/`:

- `01_velocity_profile.png` — radial profile, CFD vs analytical, three stations;
- `02_fields_velocity.png` — meridional velocity maps (CFD, analytical, difference);
- `03_pressure.png` — reconstructed pressure drop vs analytical;
- `04_metrics_summary.png` — value comparison (CFD vs analytical, error, criterion).

To regenerate them alone (after a solver run):

```bash
~/data/venvs/sgk-mini/bin/python validation/plot_annulus.py
```
